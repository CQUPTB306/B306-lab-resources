# CQUPT-B306 网站

面向新成员的文档网站，使用 HTML、CSS 与原生 JavaScript，无依赖安装或打包步骤。内容围绕学习方法、开发与协作、C 语言实践、嵌入式与智能系统、网络与 AI 工具、校园生活组织，同时保留招新与年度资料、公开项目和成员记录入口。

## 本地预览

在项目根目录运行：

```sh
python3 -m http.server 8000
```

然后访问 <http://localhost:8000>。Windows 使用 Python 启动器时可运行 `py -m http.server 8000`。页面采用 hash 路由，静态托管无需 URL 重写。

## 页面与内容维护

| 维护内容 | 文件 | 页面示例 |
| --- | --- | --- |
| 学习路径、栏目顺序、阅读准备、目标与练习建议 | `learning-paths.js` | 文档目录、侧栏、同主题前后页 |
| 首页、目录导语、关于、项目、日常 | `site-pages.js` | `#/`、`#/docs`、`#/projects` |
| 学习指南、GitHub 贡献、工具说明 | `app.js` 的 `pages` | `#/ask`、`#/contribute`、`#/pi` |
| C 语言起步、原件转述、招新索引 | `app.js` 的 `pages` | `#/c-start`、`#/c-round1`、`#/recruit` |
| 技术专题与校园指南 | `topic-pages.js` | `#/mcu-architecture`、`#/cqupt-survival` |
| 路由、导航、搜索、主题切换 | `app.js` | 全站 |
| 顶栏与框架 / 全站样式 | `index.html` / `styles.css` | 桌面、手机及浅色/深色主题 |
| 教学图示 | `assets/topics/` | 提供桌面与手机版本、alt 文本和图注 |

加载顺序为 `learning-paths.js` → `site-pages.js` → `topic-pages.js` → `app.js`。`app.js` 汇总页面后，根据路径数据生成目录、学习任务和关联阅读。目录与前后页只使用同一主题中的顺序，避免跨主题跳转。

### 新增或修订文档

1. 定位页面对象，修改 `title`、`lead`、`content`、`toc`。普通内容是 JavaScript 模板字符串中的 HTML，不是 Markdown 文件；注意反引号、反斜杠和 HTML 转义。
2. 新增教学页面时，在 `learningPaths` 对应主题加入页面 ID 和导航名称，在 `readingGuides` 中填写先备知识、目标、可验证的练习产出和关联页面。
3. 章节标题的 `id` 与 `toc` 项保持一致。“学完后做什么”由渲染层统一追加，不需重复填写。
4. 链接采用 `#/页面ID/章节ID`。文献引用的页内锚点在汇总时会转换为完整路由，保证可分享与刷新；旧目录章节别名在 `app.js` 的 `chapterAliases` 维护。改名时保留旧链接兼容关系。
5. 修改流程或架构时同步检查图示；优先沿用 SVG 风格，确认手机上文字仍清楚。字体使用本机字体，不依赖外部服务。
6. 按页面实际内容检查来源、链接、显示与交互，再发起 PR。首次贡献的完整操作示例见 `#/contribute`。

## 原始资料与修订边界

`dcos/` 的四份原件仅在维护者本地保留，不覆盖、不删除，也不随 Git 仓库上传。`docs/` 与 `dcos/` 均已加入 `.gitignore`。网页可直接阅读其中的核心学习要求、题目和框架，分别对应阶段规划、两轮打卡与打卡说明。年份依据文件明确列出的 2026 年日期；归档不代表活动已执行，也不代表当前接收报名或提交。

本次整理补充了以下差异说明：

- 原规划覆盖三周打卡，但目前仅收录两轮任务；题目测验 PDF、第三周任务和线下批次等尚未收录。`#/c-start` 中的后续学习建议不代替缺失的原始任务。
- 第二轮截止日期与“每周周一 0 点公布成绩”的说明不能直接套用，需当期负责人核实。
- 第一轮笔记允许 DOC、DOCX 或 PDF，第二轮仅允许 PDF；首周说明中有一次格式/命名问题的例外，网页明确保留适用范围。
- 第二轮位运算提示中的普通二进制与 8421 BCD 概念、字符串输入边界采用编者注说明；不改写原题、不补作业答案。

网页注明原文件名，保留原任务与编者注的区别。新增年度应创建独立页面，保留旧页面地址，更新年度索引和来源记录。缺失信息标为待确认，不推断年份、时限或规则。

原件含个人联系方式，网页不转录邮箱、不提供原件下载链接。部署脚本只复制公开网站文件与 `assets/`，不会将 `docs/`、`dcos/` 或维护文件放入发布包。内容不得包含密钥、令牌、个人隐私或未经许可的内部信息。

## GitHub Pages 发布

`.github/workflows/pages.yml` 在 `main` 分支推送后检查 JavaScript 语法，调用 `scripts/build_site.py` 生成 `_site/`，再部署到 GitHub Pages。

首次发布需由有权限的账号在仓库 **Settings → Pages → Build and deployment** 中选择 **GitHub Actions**。此后每次推送 `main` 都会更新网站，最终访问地址可在 Pages 设置页及部署记录中查看。

本地检查与预览实际发布包：

```sh
python3 scripts/build_site.py
python3 -m http.server 8000 --directory _site
```

发布包只包含 `index.html`、CSS、四个页面/导航脚本、站点标志与 `assets/`。`docs/`、`dcos/` 不进入 Git 历史，也不进入部署产物。源码中的原件文件名仅用于追溯，不是公开下载地址。

## 检查

需要 Node.js 执行语法检查：

```sh
node --check learning-paths.js
node --check site-pages.js
node --check topic-pages.js
node --check app.js
```

界面修改必须实际预览桌面与手机页面，包括浅色/深色主题、首页、文档、资料索引和成员栏目。检查页面与章节链接、图示、代码/表格溢出、导航开关、搜索、跳到正文、刷新、前进后退，以及文献引用。

PR 说明变更、来源、验证结果与未验证部分。工具版本、学校服务和外部研究资料会变化；语法与页面检查不能代替事实核验。
